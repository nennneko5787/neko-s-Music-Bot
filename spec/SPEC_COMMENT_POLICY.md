# SPEC_COMMENT_POLICY.md — コード内コメントの分量ルール

対象ブランチ: `lavalink` / 作成日: 2026-08-08 / 親仕様: `SPEC.md`

## 1. 決定

**説明は `spec/` に書き、コードには参照だけを残す。**

`SPEC.md` の付録A(#1〜#32)や各 `SPEC_REFACTOR_PR*.md` / `SPEC_FEATURE_ADS.md` に
既に書かれている内容を、コード側でもう一度 3〜5 行かけて説明していた。
同じ説明が 2 箇所にあると片方だけ古くなるため、コード側を参照に寄せる。

## 2. ルール

| 対象 | 分量 |
| --- | --- |
| **ファイル冒頭のコメント / モジュール docstring** | **全廃**。1 行も置かない |
| インラインコメント | 原則 1 行。`# SPEC #16: <一言>` の形 |
| 関数 / クラス docstring | 名前から読み取れないときだけ 1〜2 行 |
| 移設・リファクタの経緯 | **書かない**(git log と `spec/` が持つ) |
| 「元コードは〜だった」 | **書かない**(`spec/` が持つ) |

モジュールの概要は `spec/` 側に置く。ファイルを開いた瞬間に本題(import と定義)が
見えることを優先し、冒頭に説明ブロックを置かない。

参照の書き方:

- `SPEC.md` 付録A の番号 → `# SPEC #16: ...`
- 不変条件 → `# SPEC §5.2: ...`
- 機能仕様 → `# SPEC_FEATURE_ADS §4.1: ...`
- 設計判断 → `# SPEC_REFACTOR_PR8.md §3.2: ...`

## 3. 残してよい例外

- `# noqa: XXX — 理由` は ruff が必要とするため理由込みで残す
- ライブラリ側の非自明な挙動に依存している箇所(例: `deferred_message_update` の編集対象)は、
  仕様書を開かずに読めることに価値があるため 1〜2 行まで許容する

## 4. 詳細の所在

| 内容 | 所在 |
| --- | --- |
| 既知バグ #1〜#32 の詳細 | `SPEC.md` 付録A / §8.1 |
| 文字列・環境変数・命名の契約 | `SPEC.md` §5 |
| パネル / dispatch の設計 | `SPEC_REFACTOR_PR8.md` |
| 広告機能 | `SPEC_FEATURE_ADS.md` |
| 各リファクタの背景 | `SPEC_REFACTOR_PR1〜7.md` |
